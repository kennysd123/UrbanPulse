![Diagrama del enfoque arquitectónico de UrbanPulse](<../diagramas/enfoque-arquitectonico.png>)

UrbanPulse aplica **Clean Architecture dentro de un monolito modular**. Sus cuatro capas separan **Presentación, Aplicación, Dominio e Infraestructura**. El dominio define puertos para repositorios y servicios; la infraestructura los implementa y conecta la base de datos relacional y los servicios externos de mapas, WhatsApp y pagos electrónicos reales para el propietario receptor (objetivo del MVP). Así, las dependencias se orientan hacia el dominio y las integraciones quedan desacopladas.

Aplicación coordina casos de uso y consume abstracciones hacia el núcleo; su ubicación exacta se diseña según el cliente. Dominio expresa reglas sin depender de Infraestructura, SDK o clientes técnicos. Compartir monolito/base no permite acceso a tablas privadas ajenas. REST corresponde a web–backend; motor relacional, ORM, lenguaje y framework siguen sin selección.

El cliente elige total o adelanto configurado; backend verifica y aplica una sola vez. Confirmar exige además disponibilidad válida sin incompatibles concurrentes y aceptación interna en eventos; consultar no retiene. La recepción posterior del saldo completo positivo se declara por propietario autorizado y no acredita aprobación electrónica o liquidación. UrbanPulse no redistribuye manualmente fondos.

El [catálogo de doce ADR](../01-analisis-de-sistema/07-decisiones-arquitectonicas.md) mantiene ADR-001–ADR-009 adoptadas, ADR-010/ADR-011 cerradas conceptualmente y ADR-012 propuesta. Mercado Pago Marketplace Split 1:1 es candidato pendiente de validación. Las [seis fuentes C1–C4](../04-modelo-c4/01-contexto-c1.md) ya existen; conservan ocho módulos, cinco contenedores internos y seis responsabilidades técnicas conceptuales. PNG históricos pendientes de actualización. Redis solo fichas públicas reconstruibles; RabbitMQ solo invalidaciones técnicas con consumidor interno. Worker independiente: **Preparado arquitectónicamente, no obligatorio inicialmente**; implementación posterior sin modificar Dominio. No se aprueban mecanismos pendientes, integración o producción.
